## Находки

### 1. Задание пропадает ровно там, где оно нужнее всего — на экране голосования. Severity: major (продуктовый)

`renderFinal()` на доске (`auction-board.html`) и на пульте (`auction.html`) подписывает задание
только в ветке с готовыми результатами. В ветке `s.voting` задания нет ни на доске
(«Голосование — Судья недоступен или выбрано голосование. Каждый голосует с телефона за чужой
лайнап»), ни на пульте («Голосуй. За чужой лайнап, один голос»).

Почему это важно:

* «Голосование» — штатный выбор в лобби, и при нём задание вообще ни на что не влияет,
  кроме текста на экране. Убрать текст = убрать фичу.
* В эту же ветку попадает фолбэк, когда ИИ-судья не ответил (`judge_failed`).
* При задании «Худший набор» игрок, которому предложили «проголосовать за чужой лайнап»
  без напоминания критерия, проголосует за лучший — игра инвертируется.

Воспроизведение: создать комнату, в лобби выбрать «Худший набор» и судью «Голосование»,
сыграть, чтобы хотя бы у двоих был лот, «Завершить». На доске и на пульте — экран
голосования без единого упоминания задания.

**Починено** (см. ниже).

### 2. Задание не проверялось на доступность категории нигде, кроме обработчика `settings`. Severity: medium

`clampSettings` проверял только существование id задания, а проверка «доступно ли задание этой
категории» жила в одном месте — в `handle()` → `case "settings"` и только внутри `if (msg.settings)`.
Мимо неё проходили три пути, и во всех задание доезжало до промпта судьи:

```
# A. создание комнаты публичной апишкой
curl -s localhost:3000/auction/api/rooms -H 'Content-Type: application/json' \
  -d '{"kind":"food","settings":{"mode":"villains"}}'
# было: settings.mode = villains для блюд (судья получал «команда суперзлодеев» из еды)

# B. смена категории сообщением без блока settings
{"type":"settings","kind":"city"}            # mode=villains оставался от персонажей

# C. вторая партия с другой категорией
{"type":"next_game","kind":"city"}           # mode=villains переезжал в города
```

Последствия: судья судит по заданию, которого в этой категории нет; на доске в лобби при этом
не подсвечена ни одна плитка задания (плитки строятся из `modesForKind`), а на пульте у игроков
написано «😈 Лига суперзлодеев» для городов. Случай C достижим и из интерфейса, если кнопку
«Другая категория» когда-нибудь научат слать `kind` (сейчас она шлёт `next_game` без него).

**Починено** (см. ниже).

### 3. Пульт врёт про задание, если `auction-modes.js` не загрузился. Severity: medium

`modeNow()` в `auction.html` при отсутствии `window.auctionModeById` возвращал жёстко зашитый
объект «🏆 Лучший набор». То есть при заблокированном или недоехавшем файле игрок весь матч
видит «Лучший набор», пока сервер судит по «Худшему»: доска (у которой файл загрузился) и
пульт показывают противоположные задания.

Воспроизведение:

```
# комната с заданием worst
curl -s localhost:3000/auction/api/rooms -H 'Content-Type: application/json' \
  -d '{"kind":"artist","settings":{"mode":"worst"}}'
```
Открыть `auction.html?r=КОД` в Chrome, заблокировать `*auction-modes.js*`
(`Network.setBlockedURLs`, блокировщик рекламы, сбой раздачи статики), войти в комнату.
Было: плашка «🏆 Лучший набор … Победителя выберет ChatGPT — он ». JS-ошибок нет, всё остальное
работает.

**Починено** (см. ниже).

### 4. Доска без `auction-modes.js`: блок «Задание партии» остаётся пустым. Severity: minor, не чинил

`syncLobby()` строит плитки из `auctionModesForKind`, при отсутствии файла получает `[]`.
В итоге на экране создания комнаты есть заголовок «Задание партии — меняет, кого судья объявит
победителем», под ним пусто, а подсказка — «ChatGPT .» Страница жива, кнопка «Начать игру»
работает, партия идёт с `mode=base` (выбрать нечего — и это правильно). JS-ошибок нет.

Воспроизведение: то же, что в п. 3, но открыть `auction-board.html?r=КОД&t=ТОКЕН`.

Оставил: деградация безопасная, но блок стоило бы прятать целиком, раз выбирать нечего.

### 5. Кнопки «Ещё раз (та же категория)» и «Другая категория» делают одно и то же. Severity: minor, не чинил

`auction-board.html`, `renderFinal()`:

```js
document.getElementById("again").onclick   = () => sendMsg({ type: "next_game" });
document.getElementById("another").onclick = () => sendMsg({ type: "next_game" });
```

Обе возвращают в лобби с прежней категорией; «другую» хост потом выбирает плитками сам.
Формально не сломано (в лобби категория меняется), но подписи обещают разное поведение.
Существовало до фичи заданий — не регрессия, но рядом: именно `next_game` с `kind` был дырой
из п. 2. Оставил на продуктовое решение: либо одна кнопка «Ещё раз», либо `another` должен
слать `next_game` без сохранения категории/сразу открывать выбор.

### 6. Синхронность `auction/modes.js` и `auction-modes.js` ничем не проверялась. Severity: minor

Файлы байт в байт совпадают (проверено), но копия делается руками (`npm run sync-modes`), и
рассинхрон не ловился ничем: сервер судил бы по одному набору заданий, а страницы показывали бы
другой. Добавил регрессионный тест (см. ниже).

## Судейство: задание реально меняет вердикт

Один и тот же набор из трёх составов (`kind=artist`, 5 слотов) прогнан через реального судью
(`gpt-5.4`, ключ из Doppler) со всеми восемью заданиями:

* **p1 «рок-монолит»** — The Beatles, Radiohead, Nirvana, Metallica, Rammstein
* **p2 «винегрет»** — Иосиф Кобзон, Little Big, Björk, Скриптонит, Кино
* **p3 «поп-диско»** — ABBA, Beyoncé, Dua Lipa, Adele, Boney M.

| Задание | Порядок (оценки) |
| --- | --- |
| base | p1 96 · p3 89 · p2 78 |
| worst | **p2 96** · p3 44 · p1 31 |
| villains | p1 95 · p2 81 · p3 44 |
| apocalypse | p1 81 · p2 63 · p3 28 |
| party | **p3 95** · p2 91 · p1 88 |
| museum | **p2 97** · p1 81 · p3 58 |
| timemachine | p1 97 · p3 89 · p2 78 |
| gift | **p2 91** · p3 77 · p1 58 |

Задание работает: «худший набор» полностью переворачивает ранжирование (p1 с 96 падает до 31),
«вечеринка» и «музей» поднимают наверх разных игроков, вердикты написаны в терминах задания
(«идеальный аукционный апокалипсис», «музей музейного безумия», «пассивная агрессия в блёстках»).

Проверено и сквозняком через сервер (комната → торги → `end` → реальный судья): при `mode=worst`
на блюдах выигрывает «кулинарная авария», при `mode=gift` — «тяжеловесный гастрономический кирпич
в подарочной упаковке». То есть `settings.mode` доезжает от комнаты до промпта без потерь.

**Единственное задание, которое себя не проявило, — `timemachine`:** на этих составах оно дало
ровно тот же порядок и почти те же оценки, что и `base` (97/89/78 против 96/89/78). Критерий
«шок для современников» для музыкантов слишком сильно коррелирует с «кто известнее и мощнее».

### Фолбэк, когда судья недоступен

`startJudging()` при ошибке шлёт `judge_failed` и открывает голосование на 30 с. Задание при этом
**никак не участвует в подсчёте** — `closeVotes()` считает голоса и разрешает ничью по потраченному,
про `mode` не знает вовсе. Это нормально по архитектуре (голосуют люди), но ровно поэтому
единственный носитель задания в этом режиме — текст на экране, которого там не было (находка 1).
Проверено: `state.results.mode` = `"vote"`, `settings.mode` при этом сохраняется и подписывается
на итоговом экране.

## Доступность заданий по категориям — продуктовая оценка

Сейчас ограничение (`kinds`) есть ровно у одного задания — `villains`. Остальные шесть кастомных
доступны во всех 15 категориях.

| Категория | Заданий | Базовая рамка судьи |
| --- | --- | --- |
| animal, artist, character, club, company, person, profession | 8 | зоопарк / фестиваль / отряд / империя / портфель / ужин / экипаж |
| city, country, film, food, invention, painting, place, series | 7 (без villains) | маршрут / кругосветка / киномарафон / меню / изобретения в прошлое / галерея / тур / сезон |

Что я считаю проблемным — по убыванию:

1. **`apocalypse` в «картинах» (и, слабее, в «фильмах», «сериалах», «достопримечательностях»)
   — задание не различает игроков, а просто всех унижает.** Прогон на реальном судье
   (`painting`, 3 состава по 4 картины): base дал 98 / 91 / 86 и осмысленный разбор, `apocalypse` —
   **18 / 11 / 7**, все три вердикта об одном («красиво, но не греет, не кормит, не защищает»),
   а наверху оказался тот же состав, что и в base. То есть задание сводится к «у кого картины
   известнее», только с обидными цифрами. Рекомендация: добавить `apocalypse` список `kinds`
   (профессии, изобретения, животные, еда, персонажи, известные личности) и убрать оттуда
   картины/фильмы/сериалы/достопримечательности.
2. **`apocalypse` дублирует базовую рамку «профессий», `timemachine` — базовую рамку «изобретений».**
   Базовая рамка профессий — «экипаж для выживания на необитаемом острове / выживут ли»; базовая
   рамка изобретений — «набор изобретений, который берём в прошлое / насколько изменят историю».
   Судья всё же ранжирует их по-разному (на профессиях base дал p1 91 / p2 84, apocalypse — p2 96 / p1 78;
   на изобретениях base p1 98 / p3 84 / p2 72, timemachine p1 98 / p2 74 / p3 61), но для игрока
   это два тайла с одной и той же обещанной целью. Стоит либо развести формулировки `FRAMES`
   в `judge.js`, либо не предлагать эти пары.
3. **`villains` не предлагается для «изобретений»**, хотя «злодейский арсенал» ложится туда лучше,
   чем несколько заданий, которые там есть. Остальной список `villains` (персонажи, личности,
   животные, музыканты, клубы, компании, профессии) подобран здраво: картины, города, блюда,
   фильмы исключены правильно.
4. Опасения про `party` в «городах» не подтвердились: судья выдал совсем другой порядок, чем base
   (base: Париж/Лондон/Нью-Йорк/Токио 95, party: Гавана/Рио/Сан-Паулу/Буэнос-Айрес 96), и
   вердикты честно про вечеринку. Оставлять как есть.

## Что проверено и оказалось в порядке

* **Все 8 заданий** выбираются на доске, доезжают до сервера (`state.settings.mode`), подсказка
  под плитками меняется и отдельно формулируется для судьи «ChatGPT» и «Голосование».
* **Видимость по фазам**: лобби пульта (плашка «Задание партии»), шапка доски (`#gtask`) и пульта
  (`.taskbar#task`) в торгах, **на паузе задание остаётся на обоих экранах** (проверено:
  `#gtask` = «🔥 Худший набор — …», `#task` = то же, поверх пульта оверлей «Пауза — ждём ведущего»),
  итоговый экран доски (`.ftask`) и пульта (`.taskbar`). Провал был только на экране голосования
  (находка 1) — починено, теперь закрыто тестом.
* **Переподключение игрока**: закрыть сокет в середине партии и войти по токену — `settings.mode`
  и лоты на месте, задание на пульте то же.
* **Перезапуск сервера**: комната с `mode=museum` дважды пережила `SIGTERM` + старт (дамп
  `state/rooms.json`) — и в торгах, и на стадии голосования. После рестарта `settings.mode` =
  `museum`, голосование дособиралось (`armVoting`), партия не подвисла.
* **Мусор в `mode` по WebSocket**: `__proto__`, `constructor`, `toString`, `hasOwnProperty`,
  число, `null`, массив — всё откатывается к `base`, сокет жив, прототип не отравляется
  (`modeById` ходит через `Object.fromEntries`-карту, но `clampSettings` дополнительно сверяет
  `modeById(id).id === id`).
* **Задание + голосование**: `settings.judge = "vote"` не ломает задание, оно подписано в лобби
  («Победителя выбираете вы — голосованием») и на итогах («… — голосование выбирало победителя»).
