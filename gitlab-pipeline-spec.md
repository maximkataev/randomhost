# Спецификация: GitLab Pipeline & Git Blame Randomizer («Кто сломал прод?»)

## 1. Концепция
Интерактивный IT-рандомайзер для выбора случайного участника (дежурного, ответственного за инцидент, ревьюера, ведущего дейли/ретро), стилизованный под интерфейс **GitLab CI/CD Pipeline (Dark Theme)**.

Имитирует прогон автоматического пайплайна сборки и деплоя в прод, который на финальной стадии эпично падает (`Pipeline #481029 FAILED ❌`). Включается тревожная сирена и красная световая авария, а консоль раннера автоматически запускает `$ git blame` на упавшую строчку кода, драматично перебирает авторов коммитов и подсвечивает виновника с его нелепым коммитом и оправданием.

---

## 2. Архитектура и принципы
1. **Zero-Backend / Full Client-side Simulation:**
   - Вся логика сборки, терминального вывода, тревожной сирены, световых эффектов и выбора победителя работает на чистом клиенте (HTML5 / Vanilla JS / Web Audio API).
2. **Взвешенный выбор (Weighted CDF):**
   - Учитывает индивидуальные вероятности участников (`shared_probabilities_v2`).
3. **Единый сторадж проекта:**
   - Список участников сохраняется в `localStorage` по общим ключам (`shared_names_v1`, `shared_probabilities_v2`, `shared_locked_v1`).
4. **Мультиязычность:**
   - 3 языка: Русский (RU), Английский (EN), Греческий (EL) через `window.I18N_DICT` и `i18n.js`.
5. **Динамичное аудио-оформление (Web Audio API):**
   - Процедурные звуки переключения стадий, стриминга логов, двухтональная аварийная сирена при краше билда, тикающий пульс перебора коммитов и фанфары победы.

## 3. Элементы интерфейса

### Левая колонка — Панель участников (Стандартный стиль проекта)
- Заголовок «👥 Участники».
- Кнопка «Уравнять вероятности» (`equalizeBtn`) + тумблер звука (`soundToggleBtn`).
- Таблица участников: имя, кнопки +/- и поле прямого ввода вероятности с валидацией, кнопка удаления.
- Поле добавления нового участника (до 20 человек).
- Блокировка панели на время прогона пайплайна.

### Правая колонка — GitLab CI/CD Workspace
1. **Хедер проекта GitLab:**
   - Логотип лисы GitLab 🦊.
   - Хлебные крошки: `root / prod-backend > Pipelines > #482910`.
   - Бейджи статуса: ветка `main`, коммит `[c831a90]`, динамический бейдж статуса `READY / RUNNING / FAILED`.
2. **Граф стадий пайплайна (Pipeline Stages Graph):**
   - `prepare` ➔ `build` ➔ `test` ➔ `security` ➔ `deploy`.
   - Стадии анимируются: статус *pending* (серый) ➔ *running* (спиннер) ➔ *passed* (зеленая галочка `✓`) ➔ на деплое *failed* (красный крестик `✕`).
3. **Терминал / Job Trace Console (GitLab Runner Output):**
   - Темный терминал с нумерацией строк и ANSI-подсветкой.
   - Стриминг логов сборки с предупреждениями и юмором.
   - При сбое деплоя: тряска окна (glitch shake), красная аварийная подсветка экрана и двухтональная сирена.
4. **Интерактивный Git Blame Trace (Поиск автора):**
   - Команда: `$ git blame -L 1337,1337 backend/main.rs --line-porcelain`.
   - Интерактивный радар-блок перебора коммитов с хешами, авторами и диффами с экспоненциальным замедлением (easing countdown) до фиксации на виновнике.
5. **Передизайненная главная кнопка запуска:**
   - Огненно-оранжевый градиент GitLab (`#fc6d26` -> `#e24329` -> `#fca326`), мощная неоновая подсветка, анимированный блик (`::before`), текст `🦊 🚀 ЗАПУСТИТЬ PIPELINE`.

### Модальное окно победителя (Winner Modal)
- Бейдж со значком `🚨 ПАЙПЛАЙН СЛОМАН! ВИНОВНИК НАЙДЕН!`.
- Имя автора коммита в сияющем градиенте.
- Сгенерированный код диффа коммита + классическое оправдание разработчика.
- Плашка с наказанием/вердиктом («🍕 Назначается главным дежурным на выходные и покупает пиццу команде!»).
- Кнопки: «🔄 Перезапустить пайплайн (Retry Pipeline)», «❌ Исключить и крутить снова».

## 4. Сценарии инцидентов и упавших коммитов
Банк реалистичных и смешных ошибок коммитов с оправданиями:
- `+ db.drop_all(); // временный фикс для тестов, забыл удалить перед коммитом`
- `+ payment_amount = -99999.00; // бесплатная промо-акция для всех клиентов`
- `+ bypass_auth = true; // менеджеры попросили доступ на выходные без логина`
- `+ while(true) { spawnThread(); } // увеличил пропускную способность микросервиса`
- `+ eval(request.body.code); // горячий костыль для фронтендеров`
- `+ console.log(hugePayload); // логировал каждый байт трафика в stdout`
- `+ chmod 777 -R / && rm -rf /tmp /var; // починил ошибку прав доступа`
